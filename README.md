# M.Tech Project — PEFT-SLM Document Analysis

**Title:** A Study on Parameter-Efficient Fine-Tuning of Small Language Models for Document Analysis  
**Area:** Natural Language Processing · Small Language Models · Document Intelligence  
**Phase 1 scope:** Semester 3 — SQuAD QA + XL-Sum summarization (text-native tasks)

---

## Research Question

> Can PEFT-adapted Small Language Models achieve competitive performance on
> selected document-analysis tasks while offering measurable computational-efficiency
> advantages over larger models?

---

## The Core Experiment

Three models are compared on **identical test examples** (same seed, same task,
same prompt format):

| Model | Method | Parameters | Role |
|---|---|---|---|
| `Qwen/Qwen1.5-0.5B` | Base, zero-shot | 500 M | Untuned SLM baseline |
| `Qwen/Qwen1.5-0.5B` + LoRA | PEFT fine-tuned | 500 M + 0.169% adapter | **Research contribution** |
| `Qwen/Qwen1.5-7B` | Base, zero-shot | 7 B | Larger-model baseline (a reference, not an upper bound) |

All three use `model_variant: "base"` and `seed: 42`.

---

## Phase 1 Results — SQuAD v2 QA

500 held-out test questions (250 answerable, 250 unanswerable), seed 42, same prompt and
generation-based scorer for every row. Run on a Google Colab T4 (2026-10-17) with
`notebooks/simple_pipeline.ipynb`; raw files in `experiments/simple/`.

| Setup | EM | F1 | Answerable EM | Unanswerable EM | Latency / answer |
|---|---|---|---|---|---|
| Qwen1.5-0.5B, zero-shot | 5.6 | 16.39 | 11.2 | 0.0 | 191 ms |
| **Qwen1.5-0.5B + LoRA (ours)** | **68.8** | **72.44** | **66.4** | **71.2** | **150 ms** |
| Qwen1.5-7B, zero-shot (4-bit) | 27.8 | 36.55 | 55.6 | 0.0 | 1139 ms |

- LoRA trains **0.169 %** of parameters (786,432 / 464,774,144): 3 epochs, **21 min**, **4,978 MB** peak GPU.
- LoRA lifts the 0.5B model from **5.6 → 68.8 EM**; on answerable questions alone it also beats the
  zero-shot 7B (66.4 vs 55.6 EM). Neither zero-shot model ever answers "unanswerable".
- Latency is measured in our setup (7B in 4-bit at batch 4, 0.5B in fp32 at batch 8).

## Quick Start

**Reproduce the Phase 1 experiment (recommended):** upload
[`notebooks/simple_pipeline.ipynb`](notebooks/simple_pipeline.ipynb) to Google Colab, choose a
**T4 GPU** runtime and **Run all**. Run once with `DRY_RUN = True` (~5 min check), then with
`DRY_RUN = False` (~1.5 h). The notebook is self-contained and is generated by
`python notebooks/build_simple_notebook.py` — edit the builder, not the `.ipynb`.

**Use the library locally:**
```bash
pip install -r requirements.txt
python tests/smoke_test.py        # 9 end-to-end pipeline checks (CPU, downloads the 0.5B model)
```

## Key Design Decisions

1. **Base not instruct**: All three comparison models use `model_variant: "base"`.
   Mixing base and instruct variants is not a fair comparison.

2. **Seed=42 everywhere**: Ensures all three models evaluate on the exact same
   500 test examples. Verified in `tests/smoke_test.py`.

3. **Prompt masking**: Training loss is computed only on completion tokens
   (labels[prompt_len:] = actual ids). Prompt tokens are masked with -100.

4. **Skip truncated examples**: If truncation removes all answer tokens, the
   example is skipped entirely rather than training on prompt-only tokens.

5. **Unanswerable breakdown**: EM and F1 are reported separately for answerable
   and unanswerable questions to prevent score inflation.
